## Idempotent Loading

The migration/seed must be safe to execute multiple times.

Do NOT blindly execute:

```sql
INSERT INTO [dbo].[TBL_MIS_CRM_BUSINESS_REQ]
```

without duplicate protection.

Use an idempotent approach based primarily on `DOC_ID` and/or `DOC_CODE`, according to the existing database constraints.

Preferred logic:

1. If the record does not exist, insert it.
2. If the record already exists with the same `DOC_ID`/`DOC_CODE`, do not create a duplicate.
3. If the existing record differs from the supplied master data, update it to the supplied authoritative values.
4. Do not delete unrelated records already in the table.
5. Do not reset unrelated records.

Use a transaction:

```sql
BEGIN TRANSACTION;

-- validation
-- insert/update
-- verification

COMMIT TRANSACTION;
```

If an error occurs:

```sql
ROLLBACK TRANSACTION;
```
